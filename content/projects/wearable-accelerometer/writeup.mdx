## The Problem
Traditional velocity-based training (VBT) requires expensive, cumbersome equipment to track barbell kinematics. I wanted to engineer a portable, low-cost inertial measurement system that could calculate Mean Concentric Velocity (MCV) and Peak Concentric Velocity (PCV) in real-time, pairing directly with a custom mobile application for immediate lifter feedback.

## My Approach
Instead of relying on basic accelerometers, I built this hardware ecosystem around the **Bosch BMI270 IMU**. To ensure accurate 3D spatial orientation during dynamic lifts, I implemented the **Madgwick AHRS (Attitude and Heading Reference System)** sensor fusion algorithm.

The system architecture bridges embedded C++ firmware with a cross-platform Flutter application and a Firebase cloud backend.

### Firmware & Sensor Fusion
The wearable's logic is driven by custom C++ firmware that handles:

* **Sensor Interfacing:** Communicating directly with the BMI270 to pull high-frequency raw kinematic data.
* **Calibration Routines:** Executing dedicated scripts for Gyroscope and Magnetometer calibration to eliminate drift and hard/soft iron biases.
* **Data Processing:** Running the Madgwick filter on-device to compute stable spatial orientations before transmission.
* **BLE Telemetry:** Streaming the processed metrics via a custom Velocity-Based Training Bluetooth service (`ble_vbt_service`).

### Mobile Application (Flutter)
I developed a cross-platform companion app to ingest and visualize the BLE data stream. Key features include:

* **Live Metrics Engine:** A dedicated `metrics_calculator` and `set_tracker` to translate raw IMU data into actionable lifting metrics.
* **Data Dashboards:** Interactive UI pages, including a `metrics_dashboard_page` and `progress_chart_page`, to visualize range of motion and velocity trends over time.
* **Cloud Architecture:** Full integration with Firebase for secure authentication and Cloud Firestore to back up `workout_plan`, `set_summary`, and `rep_record` documents.
* **PDF Export:** A dedicated `pdf_export_service` allowing users to generate shareable reports of their training blocks.

## Lessons Learned
* **Sensor Fusion is Math-Heavy:** Relying purely on raw accelerometer data results in noisy, unusable velocity integrations. Implementing the Madgwick algorithm was critical for stabilizing the orientation tracking.
* **Asynchronous State Management:** Handling real-time BLE streams in Flutter while simultaneously syncing batch records to Firestore required careful architectural planning to prevent UI stutter.
* **Calibration is Mandatory:** I had to write isolated magnetometer and gyroscope calibration firmware to ensure the sensor data was strictly baselined before any lifting math could occur.
